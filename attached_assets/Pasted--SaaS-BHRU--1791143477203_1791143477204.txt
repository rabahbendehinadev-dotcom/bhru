==================================================
1. ما هو BHRU؟
==================================================

BHRU عبارة عن منصة SaaS موجهة لأصحاب سيرفرات خدمات الهواتف وUnlock والخدمات الرقمية.

لدينا مستويان مختلفان تمامًا من المستخدمين.

المستوى الأول — مشتركو BHRU

هؤلاء هم زبائني أنا.

مثال:

شركة أو صاحب Server باسم:

Fast Unlock DZ

يدخل إلى BHRU ويسجل حسابًا جديدًا.

بعد التسجيل يصبح Fast Unlock DZ مشتركًا في BHRU.

أنا، بصفتي مالك BHRU / Super Admin، أستطيع رؤية هذا المشترك داخل لوحة الإدارة الخاصة بي.

وأستطيع التحكم في:

- الحساب
- الاشتراك
- الخطة
- الرخصة Licence
- التفعيل
- تاريخ انتهاء الاشتراك
- التعليق
- إعادة التفعيل
- السماح أو منع الوصول

المستوى الثاني — زبائن المشترك نفسه

بعد تفعيل اشتراك Fast Unlock DZ، يحصل على Unlock Server Panel خاص به.

داخل هذا الـPanel، يقوم Fast Unlock DZ بإدارة زبائنه هو.

هؤلاء الزبائن ليسوا مشتركين في BHRU.

هم تابعون فقط لـFast Unlock DZ.

هذا الفصل مهم جدًا.

لا تخلط أبدًا بين:

BHRU Subscriber
و
Subscriber Customer.

==================================================

زائر
↓

↓
إنشاء حساب Business / Server
↓
يصبح Subscriber في BHRU
↓
يحصل على Subscription / Licence
↓
يسجل الدخول
↓
يدخل إلى Unlock Server Panel الخاص به
↓
يدير زبائنه وخدماته وطلباته وعمله من داخله

وأحتاج أيضًا أثناء التطوير إلى حساب خاص بي:

BHRU Super Admin

حتى أستطيع تجربة الجهتين:

A) أدخل كمالك / Admin لمنصة BHRU

B) أدخل كمشترك عادي في BHRU

هذا مهم لأنني سأقوم بإنشاء حساب Subscriber تجريبي خاص بي، وسأستعمله أثناء بناء البرنامج لكي أرى BHRU كما يراه الزبون الحقيقي.

3. LOGIN / REGISTRATION
==================================================

استعمل صورة Login / Registration التي أرفقتها كمرجع للـUX والتصميم العام.

أنشئ واجهة دخول وتسجيل احترافية جدًا لـBHRU.

الاسم الظاهر يجب أن يكون:

BHRU

لا تستعمل:

GAB
Space Unlock
DHRU

في التسجيل أريد نموذجًا بسيطًا واحترافيًا.

في النسخة الأولى يمكن أن يحتوي على:

- الاسم الكامل
- اسم الشركة / اسم السيرفر
- Username
- Email
- رقم الهاتف
- الدولة
- Password
- Confirm Password

لا تجعل التسجيل طويلًا أو معقدًا.

بعد التسجيل، اعرض للمستخدم حالة حسابه بشكل احترافي وواضح.

6. نظام الاشتراك / LICENCE
==================================================

جهز حالات الاشتراك التالية:

PENDING
TRIAL
ACTIVE
SUSPENDED
EXPIRED
REVOKED

أنا كـBHRU Admin يجب أن أملك التحكم الكامل فيها.

مثال:

زبون يسجل حسابًا جديدًا.

أراه في لوحة الإدارة:

Fast Unlock DZ

Status:
Pending

أفتح حسابه وأستطيع مثلًا تعيين:

Plan:
Professional

Status:
Active

Expiration:
04/10/2027

إذا عملت Suspend للمشترك، يجب ألا يستطيع استعمال Server Panel بشكل طبيعي.

إذا عملت Reactivate يرجع له الوصول.

مهم جدًا:

Suspend أو Expired أو إيقاف الاشتراك لا يعني حذف بيانات المشترك.

لا تحذف بياناته بسبب انتهاء أو تعليق الاشتراك.

10. DASHBOARD الخاص بصاحب السيرفر
==================================================

اتبع صورة BHRU Dashboard الحديثة التي أرفقتها كمرجع أساسي للـUX.

هذه Dashboard خاصة بصاحب Unlock Server.

لذلك:

لا تضع Add Funds كـQuick Action أساسي.

ولا تضع New Order كـQuick Action أساسي.

لأن صاحب السيرفر ليس هو الشخص الذي يقوم عادة بإرسال الطلبات لنفسه.

زبائنه هم الذين سيرسلون الطلبات له.

وصاحب السيرفر يقوم بربط Supplier / Source APIs ويقوم بإدارة الطلبات القادمة من زبائنه.

لذلك Dashboard يجب أن تركز على إدارة النشاط.

أريد Metrics مهمة مثل:

- Total Orders
- IMEI Orders
- Server Orders
- Remote Orders
- Total Customers
- Revenue
- Supplier Cost
- Estimated Profit

وأريد:

Orders Overview Chart

Orders by Status:

- Completed
- Processing
- Pending
- Rejected

وأيضًا:

- Top Services
- Recent Orders
- Recent Customers
- Supplier / API Status
- Latest Transactions
- Recent API Logs

13. SUPPLIERS / SOURCE APIs
==================================================

يجب أن تفهم هذه الفكرة من البداية.

مشترك BHRU يستطيع لاحقًا ربط Source APIs خارجية.

مثال:

Fast Unlock DZ

عنده:

Source API A
Source API B
Source API C

لاحقًا BHRU سيسمح له بـ:

- إضافة API Provider
- جلب Services
- مزامنة Services
- Mapping بين الخدمات
- جلب API Balance
- مزامنة الأسعار
- إرسال طلبات زبائنه إلى Source
- استقبال Result / Status
- حساب Supplier Cost
- حساب Profit

لكن:

لا تنفذ أي API حقيقية الآن.

استعمل Mock / Synthetic Data فقط في هذه المرحلة.

==================================================
14. CUSTOM DOMAIN
==================================================

لاحقًا كل مشترك في BHRU يستطيع ربط Domain أو Subdomain خاص به.

مثال:

Fast Unlock DZ مشترك في BHRU.

يمكنه لاحقًا ربط:

server.fastunlock.com

وزبائنه يدخلون إلى السيرفر الخاص به من هذا الدومين.

في هذه المرحلة:

جهز فقط مكان داخل Settings لـ:

Custom Domain
Domain Status
Verification Status

لا تنفذ الآن DNS Automation أو SSL أو Production Infrastructure.

15. التصميم — مهم جدًا
==================================================

أريد BHRU يبدو كمنتج SaaS تجاري Premium.

استعمل صور BHRU التي أرفقتها كمرجع بصري أساسي.

أريد Dark Professional Interface.

الألوان والـUX تكون مثل الاتجاه الموجود في الصور:

- Dark Navy / Charcoal
- Blue accents
- Green للحالات الناجحة وOnline
- Orange للتحذيرات
- Red للأخطاء وSuspended/Rejected
- Purple بشكل خفيف عند الحاجة

أريد:

- Typography احترافية
- Icons حديثة
- Tables احترافية ومضغوطة
- Spacing منظم
- Borders خفيفة
- Cards احترافية
- Buttons موحدة
- Status Badges واضحة
- Search ممتاز
- Filters ممتازة

الواجهة يجب أن تحتوي معلومات كثيرة ولكن تبقى نظيفة وسهلة.

هذا برنامج سيعمل عليه صاحب Server لساعات يوميًا.

لا أريد:

- مساحات فارغة ضخمة
- عناوين ضخمة
- تصميم Landing Page داخل Dashboard
- Animations كثيرة
- Gradients كثيرة
- Cards طفولية
- Admin Template قديم

Desktop هو الأساس، لكن التصميم يجب أن يكون Responsive.
