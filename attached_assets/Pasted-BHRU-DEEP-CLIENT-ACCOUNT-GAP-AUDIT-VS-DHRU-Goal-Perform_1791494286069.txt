==================================================
ARCHITECTURE PRINCIPLES
==================================================

Do NOT recommend copying DHRU's schema literally.

DHRU is legacy and uses many overloaded fields.

BHRU should use:
- normalized PostgreSQL tables
- immutable financial ledger
- explicit statuses
- foreign keys
- tenant isolation
- audit history
- integer money/minor units where appropriate
- strict account currency
- clear security boundaries

Never store:
- raw card data
- CVV
- plaintext passwords
- weak security question secrets
