==================================================
3. PASSWORD CHANGE
==================================================

Add authenticated password-change flow.

Require:

- current password
- new password
- confirm new password

Server-side requirements:

- verify current password
- enforce reasonable password policy
- reject reuse if current hash verifies same password
- hash using existing secure BHRU password hashing approach
- update password atomically
- record password-changed security event
- revoke other active sessions after successful change
- keep current session valid if safe, or rotate it

Do not expose password values in logs/activity.

==================================================
4. PASSWORD RECOVERY / RESET
==================================================

Implement secure customer password recovery.

Flow:

Forgot Password
→ customer submits email / username / client code as supported
→ server resolves tenant + customer safely
→ issue single-use expiring reset token
→ send/use reset flow through existing email infrastructure if available

If actual email delivery infrastructure is not yet available:
implement secure token lifecycle and reset endpoint/UI,
but do NOT fake email sending.

Return a truthful UI state.

Reset token requirements:

- cryptographically random
- store only hashed token
- single-use
- expires
- tenant/customer scoped
- invalidated after password reset
- previous reset tokens invalidated when new one is issued

Do not expose whether an account exists through public response wording.

==================================================
5. LOGIN HISTORY
==================================================

Create real login-history records for customer authentication.

Capture on successful login:

- customer
- subscriber/tenant
- timestamp
- IP address
- user agent
- result/status
- session reference if safe
- optional device/browser summary if derived safely

Do not store raw cookies or session secrets.

Also record failed login attempts where safe.

==================================================
6. FAILED LOGIN / LOCKOUT
==================================================

Implement safe rate/attempt protection at account level.

Requirements:

- failed attempt counter/window
- temporary lockout after repeated failures
- reset failure state after successful login
- security event for lockout where appropriate

Choose sensible thresholds and document them.

Do not permanently block the account due to password failures.

Account Blocked by reseller remains a separate concept.

8. REVOKE SESSION
==================================================

Allow customer to revoke an individual session.

Rules:

- can revoke only own sessions
- tenant scoped
- idempotent
- activity event recorded

Current session revoke behavior:
either:
A. allow and immediately logout
or
B. prevent revoking current session and offer Logout instead

Choose the safer/simple option and document it.
