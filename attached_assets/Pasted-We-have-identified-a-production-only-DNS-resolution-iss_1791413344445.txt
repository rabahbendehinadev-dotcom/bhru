We have identified a production-only DNS resolution issue in the BHRU Custom Domains verification flow.

Confirmed production evidence:

1. On the VPS host, public DNS resolves correctly:

dig +short TXT _bhru-verify.businesshubs.net @1.1.1.1
dig +short TXT _bhru-verify.businesshubs.net @8.8.8.8

Both return the expected ownership token.

2. Inside the BHRU Docker container, Node's default resolver fails:

require('dns').promises.resolveTxt('_bhru-verify.businesshubs.net')

returns:
ENOTFOUND

3. Inside the same container, an explicit public DNS Resolver works immediately:

const dns = require('dns');
const r = new dns.promises.Resolver();
r.setServers(['1.1.1.1', '8.8.8.8']);

r.resolveTxt('_bhru-verify.businesshubs.net')

returns the correct TXT token.
