/{public_slug}
→ validate the slug
→ reject reserved/application paths
→ resolve the subscriber server-side using subscribers.public_slug
→ verify that the subscriber is eligible to expose a public site
→ render an isolated BHRU Public Site Shell for that subscriber

For this phase, the Public Site Shell should be intentionally minimal.

Display only safe public information such as:

* business/company name
* BHRU public-site placeholder/layout
* a clear indication that this is the subscriber’s public website

Do NOT expose:

* owner/contact/private account data
* licence details
* subscription internals
* /api/state
* admin metadata
* internal IDs

Do not implement the full CMS yet.
Do not implement products, services, orders, customer login or checkout yet.
Do not implement custom domains yet.

The public website must be completely isolated from SubscriberShell.

Visiting another subscriber’s public URL must never change or inherit tenant ownership from the visitor’s authenticated subscriber session.

Existing routes must retain priority, including /login, /register, /dashboard, /settings, /m/*, /api/*, static/PWA/health routes and the configured private Platform Admin entry.

Unknown or invalid public slugs must return a genuine HTTP 404 where technically applicable, not expose subscriber information and not accidentally fall through as another tenant.

Subscriber states that are not eligible for public access must show a generic unavailable/not-found response without revealing whether the problem is suspension, expiry, licence, billing or another internal reason.

Database/service failures must not be treated as “subscriber not found”; use an appropriate generic server-unavailable response.
