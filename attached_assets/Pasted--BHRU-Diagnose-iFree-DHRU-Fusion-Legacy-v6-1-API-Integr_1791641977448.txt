# BHRU — Diagnose iFree DHRU Fusion Legacy v6.1 API Integration

## Mission

Investigate the existing **DHRU Fusion Legacy v6.1** provider integration in BHRU.

A real provider, **iFree iCloud**, consistently returns the application-level error:

`Connection test: INVALID_RESPONSE. Check endpoint, credentials and provider access permissions.`

The objective of this task is to identify the precise technical reason for the error using existing source code, official provider documentation where accessible, and safe local tests.

**This is a read-only investigation and diagnostic task. Do not implement a fix yet.**

- Provider name: `ifree`

- Currency: `USD`

## 2. Inspect existing BHRU implementation

Trace the complete connection-test workflow:

1. Frontend `API Settings` form.
2. Provider type selection.
3. Endpoint normalization and validation.
4. Backend route used by `Test connection`.
5. Provider adapter implementation.
6. Authentication parameter construction.
7. HTTP request execution.
8. Upstream response handling.
9. Mapping of failures to `INVALID_RESPONSE`.
10. Provider credential encryption/decryption and configuration-readiness checks.

Identify the exact source files and relevant functions.

Determine whether the Legacy adapter sends requests using the proper HTTP method, content type, field names, URL, and required DHRU v6.1 protocol parameters.

Do not assume that the implementation is correct simply because it is labeled Legacy v6.1.

## 3. Diagnose INVALID_RESPONSE

Find every code path that returns `INVALID_RESPONSE`.

For each one, identify the underlying condition, for example:

- Unexpected response format.
- HTML returned instead of JSON or XML.
- Incorrect API action.
- Authentication or permission rejection.
- Incorrect request parameters.
- HTTP response status.
- Unexpected provider response schema.
- Redirect to a web page.
- Network or TLS error.
- Unsupported or incorrectly parsed DHRU response.
- IP Guard restriction.

Distinguish confirmed findings from hypotheses.

Check whether the current error handler hides useful non-secret diagnostic information behind the generic `INVALID_RESPONSE` label.
