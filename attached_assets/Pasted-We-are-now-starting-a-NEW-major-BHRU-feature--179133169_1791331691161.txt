The existing Public Website / Top Area / Hero / Banner implementation is APPROVED.

========================================================
1. PRODUCT VISION
========================================================

I want BHRU subscribers to be able to turn their public website into a professional online store similar in usability to modern hosted commerce platforms.

A subscriber with the E-Commerce module enabled should be able to:

- create products
- upload product images
- organize products into categories
- set prices
- manage availability
- display products publicly
- let visitors browse products
- add products to a cart
- change quantities
- checkout WITHOUT creating an account
- collect customer information
- receive the order inside the subscriber panel
- manage the order lifecycle

This must remain fully multi-tenant.

Subscriber A must NEVER see or modify Subscriber B's:
- products
- categories
- images
- carts/order data
- customers
- settings

Public Store A must NEVER render Store B data.

========================================================
2. THIS IS A PAID OPTIONAL MODULE
========================================================

E-Commerce must NOT automatically be available to every subscriber.

Create it as a subscriber module/entitlement.

Conceptually:

E-Commerce Module
- enabled
- disabled

Only Platform Admin can grant or revoke the module for a subscriber.

Subscriber users must NOT be able to activate the paid module themselves.

When disabled:
- subscriber store-management UI must not be usable
- public shop/catalog/cart/checkout routes must not expose a functional store
- existing normal public website continues working
- existing data must NOT be deleted

When re-enabled:
- previous store data must still exist

IMPORTANT:
Module disable/revoke = access restriction.
It must NEVER delete products, orders or store configuration.

- settings
